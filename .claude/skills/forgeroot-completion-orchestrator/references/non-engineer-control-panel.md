# Non-Engineer Control Panel(あなた用の操作パネル)

このファイルは、ForgeRootのオーナー(非エンジニア)がClaudeに投げる「呪文」の一覧です。
Claudeへの指示: ユーザーがこれに近い言葉を使ったら、対応する動作を実行すること。

## 基本操作

| したいこと | Claudeに言う言葉 | Claudeがすること |
|---|---|---|
| 今の状態を知りたい | 「ForgeRootを監査して」 | repo audit → 監査レポート + User Decision Card |
| 次に何をすべきか知りたい | 「次の一手を出して」 | Priority ruleで次タスクを1つ選び、Next Action Cardで提示 |
| 次のPRを進めたい | 「次のPRを作って」 | タスク選定→実装→検証→draft PR→handoffまで実行 |
| 特定タスクをやりたい | 「T047をやって」 | そのT番号のスコープを裏取りしてから bounded PR を作る |
| PRを確認したい | 「open PRをレビューして」 | pr-review-method.md の手順でレビューし、マージ推奨/非推奨を提示 |
| 危険な変更か知りたい | 「class判定して」 | safety-boundaries.md の A/B/C/D で判定し理由を説明 |
| 進捗表を最新にしたい | 「TASK_PROGRESSを更新して」 | git logと突き合わせて更新PRを作る |
| 引き継ぎを残したい | 「handoffを作って」 | handoff-method.md で作成 |
| 完成までの全体像を見たい | 「Completion Ledgerを出して」 | Phase 0〜5の達成状況を証拠付きで表にする |
| 止めたい | 「halt前提で安全確認して」 | 一切の変更を止め、進行中の作業と安全状態を報告のみ |

## 用語ミニ辞書(Claudeは専門用語の直後にこの言い換えを添える)

| 用語 | 一言でいうと |
|---|---|
| PR (Pull Request) | 「この変更を取り込んでいいですか？」という提案書 |
| draft PR | まだレビュー前の下書き状態の提案書 |
| merge | 提案を正式に取り込むこと(あなたがボタンを押す) |
| branch | 本体を汚さずに作業するための作業用コピー |
| main / default branch | リポジトリの本体。直接触ってはいけない |
| rebase | 作業用コピーを最新の本体に載せ替えること |
| conflict | 2つの変更がぶつかって自動で合体できない状態 |
| CI | push のたびに自動でテストする仕組み(ForgeRootにはまだ無い) |
| stale | 古くなって現実とズレている状態 |
| dry-run | 本番に影響しない「練習実行」 |
| manifest | 「何をするか」を書いた計画書ファイル(実行はしない) |
| handoff | 次の作業セッションへの引き継ぎメモ |

## あなたがGitHub上で押すボタン(Claudeは場所まで案内する)

- **PRをマージする**: PR ページ下部の緑色「Merge pull request」ボタン。Claudeは押せない(押さない)。マージはあなたの承認行為
- **draft を ready にする**: PRページの「Ready for review」ボタン
- **PRを閉じる(不採用)**: PRページ下部の「Close pull request」
- Claudeがマージやcloseを推奨するときは、必ず理由・危険度・取り消し方法をセットで示すこと

## 失敗したときの案内ルール(Claude向け)

- 原因候補は3つ以内に絞る
- それぞれに「確認するためのコピペコマンド」を付ける
- 「あなたのせいではない」ケース(環境・ネットワーク等)はそう明言する
- 復旧不能に見えても、Gitは履歴が残るので大抵戻せる。戻す手順を先に示して安心させる
